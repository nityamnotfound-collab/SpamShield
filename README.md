# SpamShield

SpamShield is an academic Flask web app that estimates whether manually submitted
messages or URLs contain common spam and phishing warning patterns. It never
accesses an inbox, and it analyzes URL text without opening or visiting the URL.

## Features

- Message estimates from a locally trained TF-IDF and Multinomial Naive Bayes model.
- Separate rule-based checks for common message warning patterns.
- Pattern-based URL risk estimates; no network requests or threat-intelligence lookup.
- MongoDB Atlas storage, with a local SQLite fallback.
- Dashboard counts, recent activity, searchable history, and scan reports.
- Model evaluation metrics generated from a held-out test split.
- Responsive interface with dark and light themes.

All classifications are estimates, not guarantees. SpamShield does not verify
message senders.

## Installation

Install Python and pip, then open a terminal in the project root (the directory
containing `requirements.txt`).

### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If PowerShell prevents environment activation, use Command Prompt instead:

```bat
.venv\Scripts\activate.bat
```

### macOS or Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## Run from VS Code

1. Open the SpamShield project folder in VS Code.
2. Select the Python interpreter inside `.venv` using **Python: Select
   Interpreter** from the Command Palette.
3. Open **Terminal → New Terminal**. Confirm the terminal is in the project
   root and activate `.venv` using the command for your operating system above.
4. Configure MongoDB Atlas or use the SQLite fallback, then start the app:

   ```text
   python app.py
   ```

5. Open <http://127.0.0.1:5000/> in a browser. Stop the server with `Ctrl+C`.

## MongoDB Atlas setup

MongoDB Atlas is optional. When `MONGODB_URI` is not set, SpamShield uses
SQLite at `database/spamshield.db`.

1. Create a MongoDB Atlas account and a cluster.
2. In **Database Access**, create a database user with a username and password.
   Grant only the permissions needed to read and write the SpamShield database.
3. In **Network Access**, allow the IP address from which you will run SpamShield.
   Avoid allowing access from all IP addresses unless you understand the risk.
4. In the cluster's **Connect → Drivers** instructions, copy the connection
   string. Replace its username and password with the database user's values.
   Percent-encode reserved characters in the password if Atlas requires it.
5. If you do not already have a `.env` file, copy `.env.example` to `.env`.
   Do not overwrite an existing `.env`. Set the values in `.env`:

   ```dotenv
   MONGODB_URI=mongodb+srv://YOUR_USER:YOUR_PASSWORD@YOUR_CLUSTER.mongodb.net/
   MONGODB_DB_NAME=spamshield
   SECRET_KEY=replace-with-a-private-random-value
   ```

   Keep `.env` private; it is excluded by `.gitignore`. The example file uses
   placeholders and should not contain real credentials.
6. Start the app with `python app.py`. Startup initializes the configured
   database and creates the scan date index.

Atlas creates the database and collection when the first scan is saved. If
`MONGODB_URI` is absent or empty, the app selects SQLite automatically; the
SQLite database folder is created as needed.

## Deploy with Render and Vercel

The GitHub repository is configured for both platforms. `render.yaml` defines
a Render web service, and `vercel.json` routes Vercel requests to the `wsgi.py`
Flask function. Vercel installs the pinned dependencies from `pyproject.toml`;
`requirements.txt` mirrors them for local setup and Render. The function bundles
the model, templates, and static assets it needs.

Configure MongoDB before deploying. Add the Atlas URI as a secret environment
variable in each platform's dashboard; do not put real credentials in
`render.yaml`, `vercel.json`, or GitHub.

### Render

1. Sign in to the [Render Dashboard](https://dashboard.render.com/) and choose
   **New → Blueprint**.
2. Connect `nityamnotfound-collab/SpamShield` and select the `main` branch.
   Render reads `render.yaml` and configures the Python build and Gunicorn WSGI
   start command. The WSGI entry point initializes the configured database.
3. Set `MONGODB_URI` for the service to your Atlas connection string. The
   Blueprint provides `MONGODB_DB_NAME=spamshield` and generates `SECRET_KEY`.
4. Apply the Blueprint and wait for the service to finish deploying. Open the
   `onrender.com` URL shown in the service dashboard.

Render can use the SQLite fallback if `MONGODB_URI` is not set, but its local
filesystem is not durable across service replacement or deploys. Use MongoDB
Atlas for persistent scan history.

### Vercel

1. In the [Vercel Dashboard](https://vercel.com/dashboard/), choose **Add New →
   Project** and import `nityamnotfound-collab/SpamShield` from GitHub.
2. Use the repository root as the project root. The checked-in `vercel.json`
   builds `wsgi.py` with `@vercel/python` and routes all requests to it.
3. In **Project Settings → Environment Variables**, set `MONGODB_URI`,
   `MONGODB_DB_NAME` (`spamshield`), and a private `SECRET_KEY` for the
   environments you will deploy (Production, and Preview if needed).
4. Deploy the project and open the deployment URL shown by Vercel.

Vercel's function filesystem is not persistent, so configure MongoDB Atlas
there; do not rely on the SQLite fallback for hosted scan history. The SQLite
fallback writes to the local filesystem, which is not writable/persistent for
Vercel functions. `load_dotenv()` is harmless on Vercel, but `.env` is not
deployed; set the variables in Project Settings instead. Configure Atlas
Network Access for the outbound connections used by your Render and Vercel
deployments. Use the platforms' current networking options and avoid opening
database access broadly.

If both deployments use the same Atlas database URI and database name, they
share scan history. Separate database names or clusters keep their histories
separate. Future pushes to `main` trigger deployments after the repository is
connected in each platform.

## Generate the dataset and train the model

Generate the reproducible synthetic message dataset:

```text
python make_dataset.py
```

This writes `dataset/spam_dataset.csv`. Train or retrain the model and update
the evaluation metrics with:

```text
python train_model.py
```

Training saves the vectorizer and classifier together in
`models/spam_model.pkl`, and writes measured accuracy, precision, recall, F1,
the confusion matrix, dataset size, and training date to `models/metrics.json`.
To retrain after changing the generated data, run both commands in order.

## Seed demo scans

Add 10 analyzed example messages and 5 analyzed example URLs to the configured
database:

```text
python seed_demo_data.py
```

The examples use the same local analysis functions as the app. URLs are not
visited. Running the command again appends another set of demo scans.

To clear **all existing scan history** before adding the examples:

```text
python seed_demo_data.py --clear
```

Use `--clear` only when you intend to erase the current history.

## Run the API tests

Run the Flask test-client checks with:

```text
python test_app.py
```

The script prints PASS or FAIL for each check and uses isolated in-memory
storage, so it does not add to or clear the configured database. It still loads
the trained model for message analysis; generate and train the model first if
the model file is missing.

`test_db.py` is a database-layer diagnostic that writes test scans and calls
`clear_history()` at the end. Do not run it against a database whose history
you want to keep.

## Manual testing checklist

- [ ] Open the home page and follow the navigation links to each page.
- [ ] On the dashboard, confirm counts, the chart, and recent scans reflect
      saved records.
- [ ] On the message scanner, try a personal message and each sample button.
- [ ] Check that an empty message and a message over 5,000 characters are
      rejected; review the estimate, explanations, supplementary checks, and
      recommended action for a valid message.
- [ ] Try Copy Result and Download Report after a message analysis.
- [ ] On the URL scanner, try a familiar HTTPS URL and suspicious patterns such
      as a shortener or an IP address. Confirm the submitted URL is not opened.
- [ ] In history, search and filter records, open details, delete a record, and
      test Clear History only if you intend to remove all records.
- [ ] Open About and Model Performance; check metrics after training.
- [ ] Toggle the theme and reload the page to check that the choice persists.
- [ ] At a narrow viewport, test the hamburger navigation and horizontally
      scrollable tables.

## Troubleshooting

- **Missing model file:** Run `python make_dataset.py`, then
  `python train_model.py`.
- **Missing Python package:** Activate `.venv` and run
  `pip install -r requirements.txt`.
- **Atlas connection timeout or authentication failure:** Check the cluster
  address, database username/password, password encoding, and Atlas Network
  Access allowlist. Restart the app after editing `.env`.
- **App uses SQLite unexpectedly:** Check that `.env` exists, contains a
  non-empty `MONGODB_URI`, and is in the project root. The app loads `.env`
  when it starts.
- **Model Performance says metrics are unavailable:** Run `python train_model.py`
  and confirm `models/metrics.json` was created.
- **Dashboard or history is empty:** These pages show saved scans only. Analyze
  a message or URL, or run `python seed_demo_data.py` to add examples.
- **Database diagnostic cleanup:** `test_db.py` clears history when it finishes;
  use it only with a disposable database.

## Limitations

SpamShield predictions are estimates and can be wrong. The model was trained
on a synthetic dataset, which may not represent every real-world message,
language, or scam pattern. Users must independently verify suspicious messages
through an official, known channel and must not treat a SAFE result as proof
that a message is legitimate. Never share an OTP, password, UPI PIN, or payment
details in response to a suspicious request.

URL checks are pattern-based only; SpamShield does not visit URLs or check them
against an external threat-intelligence database. Scan content is saved in the
configured database so it can appear in history and reports. Do not submit
content you do not want stored there.
