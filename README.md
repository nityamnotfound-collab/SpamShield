# SpamShield

SpamShield is an academic Flask web app that estimates whether manually submitted
messages or URLs contain common spam and phishing warning patterns. It never
accesses an inbox, and it analyzes URL text without opening or visiting the URL.

## Features

- Message estimates from a locally trained TF-IDF and Multinomial Naive Bayes model.
- English, Hindi, and Hinglish message analysis with supplementary warning-pattern checks.
- Pattern-based URL risk estimates; no network requests or threat-intelligence lookup.
- MongoDB Atlas storage for all accounts and scans.
- User accounts with password hashing, login lockout, and private scan history.
- A dynamic, range-selectable dashboard with charts, recent activity, and auto-refresh.
- Searchable scam-awareness guidance and an interactive Scam/Safe quiz.
- English and Hindi interface, responsive light-only layouts, and accessible controls.

All classifications are estimates, not guarantees. SpamShield does not verify
message senders.

## Installation

Install Python and pip, then open a terminal in the project root (the directory
containing `requirements.txt`).

### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If PowerShell prevents environment activation, use Command Prompt instead:

```bat
.venv\Scripts\activate.bat
```

### macOS or Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## Configure environment variables

Copy `.env.example` to `.env` and set `SECRET_KEY`, `MONGODB_URI`, and
`MONGODB_DB_NAME`. MongoDB is required; the app will not start without
`MONGODB_URI`. Replace all sample values; never commit `.env` or paste real
credentials into source files.

Generate a random key with:

```text
python -c "import secrets; print(secrets.token_hex(32))"
```

Example configuration:

```dotenv
SECRET_KEY=your-generated-private-value
MONGODB_URI=mongodb+srv://YOUR_USER:YOUR_PASSWORD@YOUR_CLUSTER.mongodb.net/
MONGODB_DB_NAME=spamshield
```

## Run from VS Code

1. Open the SpamShield project folder in VS Code.
2. Select the Python interpreter inside `.venv` using **Python: Select
   Interpreter** from the Command Palette.
3. Open **Terminal → New Terminal**. Confirm the terminal is in the project
   root and activate `.venv` using the command for your operating system above.
4. Configure `.env` as described above, then start the app:

   ```text
   python app.py
   ```

5. Open <http://127.0.0.1:5000/> in a browser. Stop the server with `Ctrl+C`.

## MongoDB Atlas setup

MongoDB Atlas is required for local and deployed runs.

1. Create a MongoDB Atlas account and a cluster.
2. In **Database Access**, create a database user with a username and password.
   Grant only the permissions needed to read and write the SpamShield database.
3. In **Network Access**, allow the IP address from which you will run SpamShield.
   Avoid allowing access from all IP addresses unless you understand the risk.
4. In the cluster's **Connect → Drivers** instructions, copy the connection
   string. Replace its username and password with the database user's values.
   Percent-encode reserved characters in the password if Atlas requires it.
5. If you do not already have a `.env` file, copy `.env.example` to `.env`.
   Do not overwrite an existing `.env`. Set the values in `.env`:

   ```dotenv
   MONGODB_URI=mongodb+srv://YOUR_USER:YOUR_PASSWORD@YOUR_CLUSTER.mongodb.net/
   MONGODB_DB_NAME=spamshield
   SECRET_KEY=replace-with-a-private-random-value
   ```

   Keep `.env` private; it is excluded by `.gitignore`. The example file uses
   placeholders and should not contain real credentials.
6. Start the app with `python app.py`. Startup initializes the configured
   database and creates the account email and scan indexes.

Atlas creates the database and collections as accounts and scans are saved.
The app stops at startup if `MONGODB_URI` is missing or MongoDB cannot be
reached; it never falls back to local storage.

## Deploy with Render and Vercel

The GitHub repository is configured for both platforms. `render.yaml` defines
a Render web service, and `vercel.json` routes Vercel requests to the `wsgi.py`
Flask function. Vercel installs the pinned dependencies from `pyproject.toml`;
`requirements.txt` mirrors them for local setup and Render. The function bundles
the model, templates, and static assets it needs.

Configure MongoDB before deploying. Add the Atlas URI as a secret environment
variable in each platform's dashboard; do not put real credentials in
`render.yaml`, `vercel.json`, or GitHub.

### Render

1. Sign in to the [Render Dashboard](https://dashboard.render.com/) and choose
   **New → Blueprint**.
2. Connect `nityamnotfound-collab/SpamShield` and select the `main` branch.
   Render reads `render.yaml` and configures the Python build and Gunicorn WSGI
   start command. The WSGI entry point initializes the configured database.
3. Set `MONGODB_URI` for the service to your Atlas connection string. The
   Blueprint provides `MONGODB_DB_NAME=spamshield` and generates `SECRET_KEY`.
4. Apply the Blueprint and wait for the service to finish deploying. Open the
   `onrender.com` URL shown in the service dashboard.

Render requires the configured MongoDB Atlas connection for accounts and scans.

### Vercel

1. In the [Vercel Dashboard](https://vercel.com/dashboard/), choose **Add New →
   Project** and import `nityamnotfound-collab/SpamShield` from GitHub.
2. Use the repository root as the project root. The checked-in `vercel.json`
   builds `wsgi.py` with `@vercel/python` and routes all requests to it.
3. In **Project Settings → Environment Variables**, set `MONGODB_URI`,
   `MONGODB_DB_NAME` (`spamshield`), and a private `SECRET_KEY` for the
   environments you will deploy (Production, and Preview if needed).
4. Deploy the project and open the deployment URL shown by Vercel.

Vercel's function filesystem is not persistent, so MongoDB Atlas is required.
If `MONGODB_URI` is missing or MongoDB cannot be reached, the function fails
at startup instead of silently using temporary storage. `load_dotenv()` is
harmless on Vercel, but `.env` is not deployed; set the variables in Project
Settings instead. Configure Atlas Network Access for the outbound connections
used by your Render and Vercel deployments. Use the platforms' current
networking options and avoid opening database access broadly.

If both deployments use the same Atlas database URI and database name, they
share scan history. Separate database names or clusters keep their histories
separate. Future pushes to `main` trigger deployments after the repository is
connected in each platform.

## Generate the multilingual dataset and train the model

Generate the reproducible synthetic message dataset:

```text
python make_dataset.py
```

This writes `dataset/spam_dataset.csv` with English, Hinglish, and Hindi
messages and a language label for each row. The generated examples include
scam and genuine messages in each supported language. Train or retrain the
model and print the evaluation metrics to the console with:

```text
python train_model.py
```

Training compares word and character-boundary TF-IDF features on a held-out
split, reports accuracy, precision, recall, and F1 overall and per language,
then saves the better vectorizer and classifier together in
`models/spam_model.pkl`. Hindi and Hinglish evaluation is an estimate and
depends on dataset size and variety; scores may be lower or vary after
regeneration. To retrain after changing the generated data, run both commands
in order.

## Seed demo scans

Add 10 analyzed example messages and 5 analyzed example URLs to an existing
account's history:

```text
python seed_demo_data.py --email YOUR_ACCOUNT_EMAIL
```

The examples use the same local analysis functions as the app. URLs are not
visited. Running the command again appends another set of demo scans. The
`--clear` option clears only the selected account's scans.

To clear the selected account's existing scans before adding the examples:

```text
python seed_demo_data.py --email YOUR_ACCOUNT_EMAIL --clear
```

Use `--clear` only when you intend to erase that account's history.

## Run the API tests

Run the Flask test-client checks and dashboard aggregation unit tests with:

```text
python test_app.py
python -m unittest test_dashboard_stats -v
```

The script prints PASS or FAIL for each check and uses isolated in-memory
storage, so it does not add to or clear the configured database. It still loads
the trained model for message analysis; generate and train the model first if
the model file is missing.

The test-client run prints an individual PASS or FAIL for each check. It uses
temporary in-memory account and scan records and clears them after the run;
the dashboard aggregation tests use representative MongoDB aggregation rows.

`test_db.py` is a database-layer diagnostic. Set `TEST_USER_EMAIL` to an
existing account before running it; it only clears that account's scans.

## Manual testing checklist

- [ ] Register with a weak password, malformed email, duplicate email, and a
      valid password; confirm inline feedback and successful registration.
- [ ] Log in with valid and invalid credentials; verify the generic error,
      five-attempt lockout, and optional seven-day remembered session.
- [ ] While signed out, confirm protected pages redirect to login and protected
      API calls return 401. Log out and verify the session ends.
- [ ] Create two accounts and confirm each account can only view and delete its
      own scans.
- [ ] Switch between English and Hindi on public and signed-in pages; verify
      the selection persists after navigation and reload.
- [ ] Scan a safe personal message, English scam, Hinglish scam, and Hindi scam.
      Confirm results, explanations, and recommended actions are estimates and
      are displayed in the selected language.
- [ ] Try the message scanner's sample buttons, empty input, overlong input,
      copy result, and download report.
- [ ] Check a familiar HTTPS URL and suspicious URL patterns such as a
      shortener or IP address; confirm the submitted URL is never visited.
- [ ] Use dashboard 7-day, 30-day, and all-time ranges; scan and delete records
      and confirm totals, charts, recent activity, and auto-refresh update.
- [ ] In history, search and filter, open scan details, delete one scan, and
      clear only the signed-in account's history.
- [ ] On Scam Awareness, search and filter topics, switch language, and finish
      the six-question quiz; review the safety steps and reporting details.
- [ ] At mobile widths and with Hindi selected, test the menu, forms, charts,
      awareness cards, and horizontally scrollable tables for overflow.

## Troubleshooting

- **Missing model file:** Run `python make_dataset.py`, then
  `python train_model.py`.
- **Missing Python package:** Activate `.venv` and run
  `pip install -r requirements.txt`.
- **Atlas connection timeout or authentication failure:** Check the cluster
  address, database username/password, password encoding, and Atlas Network
  Access allowlist. Restart the app after editing `.env`.
- **MongoDB configuration error:** Ensure `.env` contains a non-empty
  `MONGODB_URI` and `MONGODB_DB_NAME`, or set them in the hosting platform's
  environment settings. Restart or redeploy after changing variables.
- **Dashboard or history is empty:** These pages show saved scans only. Analyze
  a message or URL, or run `python seed_demo_data.py --email YOUR_ACCOUNT_EMAIL`
  to add examples.

## Limitations

SpamShield is a student project, not an official government service. Its
predictions are estimates and can be wrong. Hindi and Hinglish accuracy depends
on the size and variety of the training dataset; the synthetic examples may not
represent every real message, language variant, or scam pattern. SpamShield
does not verify who sent a message, so a SAFE result is not proof that a sender
or message is genuine. Independently verify unusual requests through a known,
official channel. Never share an OTP, password, UPI PIN, or payment details in
response to an unexpected request.

URL checks are pattern-based only; SpamShield does not visit URLs or check them
against an external threat-intelligence database. Scan content is saved in the
configured database and associated with the account that submitted it. Do not
submit content you do not want stored there.
